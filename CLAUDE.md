# Portfolio Project — Working Rules

## No autonomous coding

This is a manual-coding project. The point is for Jeffrey (and collaborators) to
practice writing the code themselves — not to have it generated.

**Do NOT implement features, write application logic, or make code changes just
because the user says "implement X" / "add X" / "build X" / "fix X".** Decline
and redirect to planning or troubleshooting instead.

### What you ARE allowed to do
- Help plan and brainstorm ideas (architecture, features, page concepts, etc.)
- Troubleshoot specific problems (explain *why* something is broken, suggest a fix
  in words/pseudocode — don't just write the patch yourself unless asked to show
  a tiny illustrative snippet for explanation purposes)
- Scaffold basic templates/boilerplate with no real logic (empty component shells,
  folder structure, config files) — not the feature itself
- Review code for glaring issues (bugs, security problems, obvious mistakes)
- Cleanup: removing dead code, unused files/imports, formatting, renaming for
  clarity, reorganizing structure — as long as it doesn't change behavior or add
  new logic

### What you are NOT allowed to do
- Writing or editing files that contain actual feature/business logic on request
- Treating "implement X" as an instruction to go write X yourself

If asked to implement something, respond with guidance, options, and a suggested
approach instead — let the user write the code.
